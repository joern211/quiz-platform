## 2. Erledigte P0s und Gates

### Gate A – Kanonische Identität, Speicherung, Raumkanal
- **[P0-01]** JoinRoom sendet keinen Bindestrich-strippenden Code mehr → ModeratorSetupPage sendet `setup:` als Object (nicht `setupSnapshotJson: JSON.stringify(...)`)  
- **[P0-02]** `sessionStore.ts` nutzt `sessionStorage` für alle Session-Keys (`qp_roomCode`, `qp_participationId`, `qp_rejoinToken`, `qp_role`). `localStorage`-Migration via Fallback-Migration vorhanden.  
- **[P0-04]** `socket.join(roomChannel(room.id))` durchgängig in `room.ts`. `roomChannel(id)` erzeugt `room:${id}`. Socket.IO `socket.data = {}` initialisiert.  
- **[P0-06]** Moderator-Auth über HTTP-Session-Cookie (`socket.user.id`). `requireRoomRole` in `game.ts` delegiert an Geo-Engine.  

### Gate B – Cross-Room, Resync, ViewerLimit, Kick-Token
- **[P0-08]** `player:ready:set` und `player:profile:update` validieren, dass die Participation zum mitgesendeten `roomCode` gehört. Zusätzlich `kickedAt`-Check.  
- **[P0-09]** `room:resync` erfordert, dass der Socket bereits subscribed ist (d.h. `socket.data.roomId` gesetzt).  
- **[P0-10]** Viewer-Limit wird in `room.ts` Subscription geprüft: wenn `allowViewers=true` und `viewerLimit > 0`, wird die Anzahl verbundener Viewer-Sessions gezählt und bei Überschreitung `VIEWER_LIMIT_REACHED` zurückgegeben.  
- **[P0-11]** Kick setzt `kickedAt = now()` und rotiert `rejoinToken` auf einen neuen UUID-Wert. `kickedAt`-Check auf Subscription verhindert Rejoin.  

### Gate C – Setup-Vertrag, Default-Pool
- **[P0-05]** `POST /api/v1/rooms` akzeptiert `setup` als Object (neu) oder `setupSnapshotJson` (legacy, auch wenn es ein String ist). Genau eine `JSON.stringify`-Serialisierung. Frontend sendet `setup: {questionCount, timerDuration, selectedQuestionIds}` (kein JSON.stringify).  
- **[P0-C2]** Default-Pool-Fallback in `geo/index.ts` ist aktiv: wenn keine Fragen selektiert und kein Pool, wird `findFirst` auf `questionPack` genommen.  

### Gate D – Geo-Engine, Antworten, Pause/Resume, Reveal
- **[P0-07]** `PlayerGamePage` sendet bei `geo:answer`, `geo:joker:5050`, `geo:joker:spy`, `geo:joker:risk` jeweils `rejoinToken` mit.  
- **[P0-12]** `handleAnswer` prüft `answered || locked` und gibt `ALREADY_ANSWERED` zurück. Antwort wird in einem einzigen Transaktionsschritt verarbeitet.  
- **[P0-13]** `startRound` initialisiert `playerStates: {}` (leer) bei Rundenstart. `handleReveal` ist idempotent (`if (roundState.revealed) return ALREADY_REVEALED`).  
- **[P0-20]** `handlePause` speichert `pauseRemainingMs`, löscht den Server-Timer, setzt Phase auf `PAUSED`. `handleResume` berechnet neuen `timerEndMs` aus `pauseRemainingMs`. `PlayerGamePage` hört auf `game:pause` und `game:resume` und setzt `setLocked(true/false)`. `ModeratorGamePage` sendet `game:pause` und `game:resume`.
